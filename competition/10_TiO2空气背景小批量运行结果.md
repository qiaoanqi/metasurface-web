# TiO₂/SiO₂/空气小批量 RCWA 运行结果

## 运行范围

这是竞赛展示专用的小批量真实前向计算，不是训练集、完整数据集或精度证明。运行配置为：

- TiO₂ 圆柱 / SiO₂ 基底 / 空气背景
- 法向入射，p 偏振
- `nG=151`，`Nxy=256`
- 波长 380–780 nm，5 nm 间隔，共 81 点
- 几何：`(D,H,P) = (120,300,360), (220,450,517), (300,250,587)` nm

## 结果

- 3/3 条记录完成，0 条失败
- 所有 R/T 数组有限，长度均为 81
- 所有样本通过逐波长 `|R+T−1| <= 1e-6` 守恒检查
- 全批次最大 `|R+T−1| = 1.30×10⁻¹²`
- 总耗时约 196.2 秒，单条约 63–69 秒
- 没有触发 Rayleigh 极限修正

## 对云服务器的建议

这台本地机器单条约 1 分钟，云端可以通过更高单核性能和受控并行缩短时间。建议先用 4 vCPU、16 GB 内存、Ubuntu 22.04/24.04，单个 worker 绑定 1 个 BLAS 线程，先跑 4 条试验再决定是否扩到 8 worker。不要让每个 worker 再开启多线程，否则会争抢内存和 CPU。

云端执行所需文件：

```text
rcwa_batch.py
paper1_rebuild_v1/colorimetry_v1.py
competition/run_tio2_air_smoke.py
```

安装依赖至少包括 `numpy`、`scipy`、`grcwa`。脚本只写 `competition/tio2_air_smoke_v2.json`，不会触碰旧池、Paper1/Paper2 或训练流程。

云端批量脚本：[`run_tio2_air_batch_cloud.py`](run_tio2_air_batch_cloud.py)。在实例上可按下面顺序执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r competition/cloud_requirements.txt
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  python competition/run_tio2_air_batch_cloud.py \
  --samples 8 --workers 4 --nG 151 --Nxy 256 \
  --output competition/tio2_air_batch_cloud_probe_v1.json
```

确认 8 条试跑全部完成、内存稳定后，再把 `--samples` 改为 32 或 64。`--workers` 建议保持 4；只有在监控确认内存余量充足时才尝试 6 或 8。每条完成记录会写入同名 `.partial.json`，SSH 断开后仍可保留已完成结果，但当前脚本不会自动从 partial 续算，续算前应先保留该文件并重新指定新的输出名。

## 当前结论

这批数据足以支持展示页中的“真实前向样本复核”和答辩演示。若要补更多样本，优先在云端按每批 4–8 条执行，并保留每批独立 JSON 与 SHA256；不要把这些 3 条直接包装为模型准确率或完整数据集质量证据。
